WHAT DID NOT WORK — LOCALLY UNCENSORED (v3.0.2, Linux AppImage)
by PurpleDoubleD — DELETED AFTER 5 REAL BUGS
================================================================

What we did: installed the AppImage to /home/nir/Apps (118MB),
wizard chose: LU Engine (its own engine, good choice) + its own
private ComfyUI at /home/nir/ComfyUI (all big partition OK),
skipped chat model + RAG (chat belongs to Unsloth Studio).

THE 5 BUGS (all verified with real evidence, not guesses):
1. LTX Video 2.3 22B FP8 recipe is broken IN THE APP:
   the hidden workflow wires VAEDecodeTiled's VAE input to
   UNETLoader's MODEL output, and there is NO VAE loader node
   at all -> ComfyUI rejects it: "Return type mismatch between
   linked nodes". (The 29.5GB checkpoint DOES contain the VAE
   inside — model/vae/audio_vae/vocoder all verified inside
   the file — the app just wired it wrong.)
2. The engine DIES SILENTLY. No engine status, no ComfyUI
   start/restart/repair button anywhere in Settings.
3. Stale model list: the Create tab's model menu shows what it
   REMEMBERS, not what is on disk (showed deleted LTX, hid the
   freshly downloaded HunyuanVideo). List only refreshes from
   the engine when the app reconnects at startup.
4. HunyuanVideo 1.5 T2V FP8 recipe is ALSO broken IN THE APP:
   CLIPLoader uses type "wan" (wrong AI family -> the model got
   the prompt as gibberish) + uses the OLD HunyuanVideo 1.0
   latent node instead of the 1.5 one (wrong film shape).
   Result: the render "succeeded" but produced a 3-second
   ACID TRIP of flashing colors — not a wave.
   (The VAE was actually fine — the 8 "missing VAE keys"
   warning is harmless, those parts are never used.)
5. Broken gallery/preview on Linux: renders SUCCEED, files
   land in /home/nir/ComfyUI/output/, but the app never shows
   them ("This render lives on the local engine, which isn't
   reachable right now").

Verdict by Nir: "complete crap" -> DELETED EVERYTHING:
- All models (Juggernaut 6.7G, HunyuanVideo 7.8G + 2.4G VAE +
  9G qwen encoder, Wan 2.2 9.4G + 1.4G VAE + umt5 + clip_l)
- Its whole private ComfyUI /home/nir/ComfyUI (31GB total freed)
- The AppImage + all its data/config folders + all its icons
- The website's own ComfyUI at /home/nir/ai-art/ was NOT
  touched and is safe.
- Nir's 2 test videos were saved to the Desktop first
  (MY-WAN-2.2-VIDEO.mp4 kept; the Hunyuan acid trip deleted).

ROOT CAUSE ANALYSIS (why so buggy):
- The app's own download page admits: Windows = "tested every
  release", Linux = "built on every release" (built != tested).
  All 5 bugs are Linux-side.
- It is a young app (new version every few days) chasing the
  NEWEST AI models weekly; each new model needs a hand-written
  recipe inside the app. Both broken recipes were for models
  released WEEKS ago (LTX 2.3, HunyuanVideo 1.5). The boring
  old stuff would have worked.
- Pattern discovered: apps that HIDE a ComfyUI and write secret
  recipes for it (Locally Uncensored) break; apps that are
  their OWN thing (WanGP) stay stable.
